# Nook

Modular alert aggregation service — watches providers, receives webhooks, and delivers notifications to Matrix, Discord, HTTP, SMTP, ntfy, and Perception. Ships with a Nuxt dashboard for configuration.

## Tech Stack

- **Runtime**: Bun
- **API**: TypeScript, runs directly via `bun run index.ts` (no framework)
- **Client**: Nuxt 4 (Vue 3), Tailwind CSS v4, static-generated SPA served at `/dashboard/`
- **Docker**: Multi-stage build (`oven/bun:1`), client pre-built then copied into API image
- **Config storage**: JSON file at `/data/nook.json` (SQLite migration planned)

## Commands

All commands run from the project root.

| Task | Command |
|---|---|
| Install deps | `bun install` |
| Run API (dev) | `bun run dev` |
| Run dashboard (dev) | `bun run client:dev` |
| Build dashboard | `bun run client:build` |
| Run tests | `bun test` |
| Typecheck API | `bun run typecheck` |

The dashboard dev server proxies API calls to the running API, so start both for full local development.

Before deploying dashboard changes, always rebuild: `bun run client:build`.

## API Routes

- `GET /health` — health check
- `GET /api/settings` / `PUT /api/settings` — config CRUD
- `POST /api/test-alert` — send a test alert
- `POST /api/login` / `POST /api/logout` — dashboard auth
- `POST /webhook/<provider>` — incoming webhook endpoints

## Environment Variables

- `PORT` — HTTP port (default: `9090`)
- `NOOK_SETTINGS_PATH` — config file path (default: `/data/nook.json`)
- `NOOK_ADMIN_PASSWORD` — enables dashboard auth if set
- `NOOK_ADMIN_USERNAME` — login label (default: `admin`)
- `NOOK_SESSION_SECRET` — session signing secret

## Testing

Tests live alongside source in `apps/api/src/` (e.g., `delivery.test.ts`). Run with `bun test`.

## Docker

```sh
docker build -t nook .
docker run -d -p 9090:9090 -e NOOK_ADMIN_PASSWORD=changeme -v ./data:/data nook
```

Or use `docker-compose.yml` at the project root.

## Conventions

- Webhook providers live in `apps/api/src/webhooks/providers/`, one file per provider.
- Delivery targets are implemented as sender functions in `delivery-senders.ts`.
- All webhook/HTTP deliveries use signed event envelopes (HMAC-SHA256).
- Provider and delivery config is managed through the dashboard, not env vars.
- The client builds to `apps/api/dashboard/.output/public` so the API can serve it statically.
